# Operations: where things run, how they ship

## Environments

- **This machine**: the sessions (CLAUDE.md "Sessions") in the one shared
  checkout on `main`; the pinned jobs' worktrees only: the training runs
  (`../zero-vtes-pN`; DESIGN §11.2) and Z-main's detached checkout at
  `main`'s tip (docs/watch.md). Shared: docs/hazards.md "The shared tree"
  and "The shared machine".
- **frankfurt**: an OVH VPS, 6 vCPU / 12 GB, shared with archon beta and
  the forum (Discourse); pyinfra-deployed systemd units behind nginx and
  certbot, sops secrets, Alloy to Loki and Prometheus, Postgres 17 with
  nightly restic backups to Scaleway, UFW 22/80/443 only. It keeps the
  served weights and their runs' checkpoints by hash in
  `/opt/zvtes/weights` ("Releases and deploys"). It serves:
  - `https://engine.krcg.org`: the server (`crates/server`, port 8040,
    `MemoryMax` 3G and `CPUQuota` 400% in `deploy/group_data/all.py`: the
    forum shares the box; the server pings every 30 s under nginx's read
    timeout), every game logged to Postgres and kept two years;
  - `https://sc-bot.krcg.org`: the Succubus Club fork, built on the box,
    niced, served as a static site (`deploy/sc_bot.py`, server-setup's
    `spa` nginx site; human-play.md "Running the fork").

## Checks

Before calling work done (ship step 3):

- `cargo fmt --check`; `cargo clippy --all-targets --profile ci -- -D
  warnings`; `cargo test --profile ci -q` (the `ci` profile: release speed
  plus debug assertions and overflow checks, incremental; no separate
  debug run) — cargo stops at the first failing binary, so sum the "test
  result" lines and grep for panics.
- `cargo test -p zvtes-api --features schema --profile ci` (the wire
  format and `crates/api/schema.json` and `openapi.json`, regenerated by
  its `schema` example, `openapi` as its argument for the latter: it
  embeds `docs/protocol.md`, so regenerate after editing that too);
  `python3 scripts/gen_ts.py --check crates/api/protocol.ts`; `python3
  scripts/schema_compat.py --check` (a field or id removed or renamed
  against `HEAD` fails unless the major moves; a protocol bump adds its
  `CHANGELOG.md` entry).
- The ledger, window-matrix and generator `--check`s (CLAUDE.md "Key
  facts"); `python3 scripts/digest_index.py --check` (rules-digest §25,
  the index of rules-qa items to the digest's sections: regenerate after
  a rules-qa or digest change); the count line at the end of DESIGN §11.
- Online play (`crates/host`, `crates/text`, `crates/server`):
  `docs/human-play.md` "Checks" (the server is not a default member).
- Python side (`crates/py`, `train/`): `uv sync` builds the extension (it
  rebuilds when Rust sources change); `uv run pytest -q`;
  `PYO3_PYTHON=$PWD/.venv/bin/python cargo clippy -p zvtes-py --profile
  ci -- -D warnings` (the py crate is not a default workspace member:
  plain cargo commands stay engine-only).

Tests: one binary per file under `crates/engine/tests/` (merging them
into one binary was measured slower to rebuild); shared helpers in
`tests/common` (`CardInPlay::new` for a card put in play).

Train: `uv run python -m train.ppo --out runs/<name>` (`runs/` is
ignored; add `--league true` for the league: bots and snapshots as
opponents (`best.pt` keeps the best evaluation against the bots);
`--resume runs/<name>/model.pt` to continue). The training skill holds
the rest.

## Releases and deploys

Every line commits to `main` itself (CLAUDE.md "Sessions"); Z-main alone
pushes `main`, tags and deploys, without asking the owner (the owner's
standing word, 2026-10-23):

- `main` pushed fast-forward only, never forced;
- a release tagged `vX.Y.Z` on `main`'s tip once its checks are green in
  Z-main's detached checkout (docs/watch.md), never in the shared one
  (it holds the lines' work in progress); the engine's Rust
  ships as a GitHub Actions release asset on a `v*` tag
  (`.github/workflows/release.yml`), never built on the box:
  `deploy/deploy.py` fetches it (`deploy/release.py`), `deploy/build.sh`
  the fallback:

  ```
  cd deploy && ZVTES_REPO=lionel-panhaleux/zero-vtes RELEASE_TAG=v<x.y.z> \
    uv run --group deploy pyinfra inventory.py deploy.py -y
  ```

  Nothing is built on this machine, so a training run need not pause.
- a deploy only with no game live (`GET /admin/games?since=<a day ago,
  Unix ms>`, protocol §10: a bare call answers the oldest 1000 only; a
  game without `ended` is live and stops it), the lines told before a
  redeploy, the client smoke test after (`node
  crates/server/tests/client.mjs https://engine.krcg.org`, Node 22 or
  later), each reported in the digest;
- weights served by the measure (training skill "Serve"): `ZVTES_WEIGHTS`
  names the weights served; their measure by deck, the training line's
  `<name>.decks.json` beside them, goes with them when it is there
  (`ZVTES_DECKS`, served at `GET /catalog/taught` only while it names the
  weights served), and their run's checkpoint, `<name>.pt` beside them,
  kept as `/opt/zvtes/weights/<sha>.pt` (owner, 2026-11-09: the one
  training file kept off the training machine, a run's `best.pt`; the
  rest of `runs/` is not kept, the harvest is rebuilt from
  the server's Postgres, the run's numbers live in DESIGN §11.2).

Z-succubus pushes its own fork branches but `engine-game` (upstream PR
#285, sc-change); upstream stays on the owner's word.

## Looking things up

Before using a library, a tool or Claude Code's own features, read the
current documentation, never memory: first the sources the pages point
at, then the lookup tools, then the official pages.

- The rules: the `vtes` skill (rulebook, tournament rules, judges'
  guides), `../vtes-advanced-rules`, the KRCG data and rulings
  (`scripts/krcg.py`), the play procedures gist (CLAUDE.md "Key facts").
- Libraries (Rust crates, PyTorch, Vue, pyinfra …): the Context7 server
  (`resolve-library-id`, then `query-docs`), then docs.rs or the
  project's pages.
- Claude Code (skills, agents, crons, `SendMessage`): code.claude.com/docs,
  or the `claude-code-guide` agent. Memory outside the repository is off
  (`autoMemoryEnabled: false` in `.claude/settings.json`); keep
  `~/.claude/CLAUDE.md` and `~/.claude/rules/` free of project facts.
